# Contribution and Review Process

1. Begin milestone work on the `development` branch.
2. Create a focused branch from `development` when a change is large enough to review separately.
3. Keep each commit limited to one meaningful documentation, design, or testing change.
4. Include a requirement identifier when the change affects a specific requirement.
5. Review documents, diagrams, and evidence before merging.
6. Merge approved focused work into `development`.
7. Merge `development` into `main` only after the milestone has been reviewed.

Useful commit-message examples include:

- `docs: define FR-01 through FR-10`
- `design: add compliance signal to access flow`
- `docs: record Apple management comparison criteria`
- `test: add evidence record for FR-05`

No contributor should commit credentials, production data, personal information, device serial numbers, tenant identifiers, or unredacted screenshots.
