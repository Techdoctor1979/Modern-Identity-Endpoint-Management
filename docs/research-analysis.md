# Research Analysis and Design Response

The reviewed sources contribute different parts of the design, but no single source provides the complete migration process required by this project.

NIST Special Publication 800-63-4 provides product-neutral guidance for identity proofing, authenticators, authentication, federation, recovery, and lifecycle management. CISA's Zero Trust Maturity Model expands the decision beyond identity by treating devices, applications, networks, and data as related security pillars. Together, these sources support MFA, separate administrative access, device-aware policy, logging, recovery, and staged enforcement. They do not prescribe how a particular organization should move its existing Active Directory dependencies or compare Intune with Addigy.

The NIST privacy sources add a different requirement. Device and sign-in information may improve security decisions, but collection can still create privacy risk. The design therefore limits PII, restricts evidence, defines retention and disposal, supports clear enrollment notices, and includes human review for access exceptions. This is important because secure storage alone does not justify collecting information that the project does not need.

Microsoft, Apple, and Addigy documentation identifies implementation capabilities. Microsoft explains the connection between Intune compliance and Entra Conditional Access. Apple explains organizational assignment and automated enrollment through Apple Business Manager. Addigy documents Apple-focused policy and device-management functions. These sources are useful for identifying possible configurations, but they describe their own platforms and are not independent comparative evaluations. A documented feature will therefore become a requirement or test candidate, not an automatic proof-of-concept result.

The practical gap is the workflow that connects these findings during a mixed Windows and Apple transition. The proposed architecture addresses that gap through seven modules covering identity integration, authentication and authorization, endpoint enrollment, configuration and compliance, Conditional Access, monitoring, and privacy governance. The temporary Active Directory path preserves approved legacy access while each dependency receives an owner, remediation method, test, target date, and exit criterion.

Requirement identifiers connect the research to the architecture and planned evidence. The same Apple-management outcomes will be tested in Intune and Addigy where access permits. Results will be recorded as Pass, Partial, Fail, or Not tested. This approach allows the final recommendation to distinguish standards-based expectations, vendor-documented capabilities, observed behavior, and limitations.
